# Инварианты и процедура эталонной проверки

Пусть состояние клиента $C_Q=\{f_1,f_2,\ldots,f_s\}$, где каждый материализованный фрагмент имеет вид $f_i=(I_i,Rows_i,v_i)$, а $F_i=F(Q,I_i,v_i)$ - эталонный фрагмент для того же запроса, диапазона и версии.

Критерий корректности фрагмента: $Correct(f_i)\iff Rows_i=F_i$. Равенство означает совпадение `rowId`, ключей $K_Q$, значений $Value_Q$ и порядка строк.

## Локальные инварианты

### 1. Уникальность `rowId`

Количество различных `rowId` внутри каждого фрагмента должно совпадать с количеством хранимых строк:

```math
\left| \{ rowId(r) \mid r \in Rows_i \} \right|
=
|Rows_i|
```

### 2. Принадлежность диапазону

Каждая строка фрагмента принадлежит его диапазону: $\forall r\in Rows_i:\ K_Q(r)\in I_i$.

### 3. Корректный порядок

Пусть $Rows_i=\langle r_1,r_2,\ldots,r_n\rangle$. Каждая следующая строка расположена позже предыдущей согласно порядку $\prec_Q$:

$$
\forall j\in\{1,\ldots,n-1\}:\ r_j\prec_Q r_{j+1}.
$$

### 4. Полнота диапазона

Набор строк клиентского фрагмента совпадает с эталонным фрагментом по `rowId`:

$$
Ids(Rows_i)=Ids(F_i).
$$

### 5. Корректность значений

Для каждой строки клиентского фрагмента существует строка эталонного фрагмента с тем же `rowId`, ключом порядка и пользовательскими значениями:

$$
\forall r\in Rows_i\ \exists r'\in F_i:
rowId(r)=rowId(r')
\land K_Q(r)=K_Q(r')
\land Value_Q(r)=Value_Q(r').
$$

## Инварианты состояния клиента

### 6. Непересечение материализованных диапазонов

Диапазоны различных фрагментов не пересекаются: $\forall i\ne j:\ I_i\cap I_j=\varnothing$.

В общем случае фрагменты могут иметь разные версии $v_i$, поэтому глобальная уникальность `rowId` не требуется.

## Нормализация состояния

Операция $Normalize(C_Q,V)$ приводит все проверяемые фрагменты к общей версии $V$.

Для каждого фрагмента $f_i=(I_i,Rows_i,v_i)$, где $v_i\le V$:

1. Если $v_i=V$, актуализация не требуется.
2. Если replay доступен, применить все релевантные изменения с версиями в интервале $(v_i,V]$.
3. Если replay недоступен, повторно получить диапазон $I_i$ из состояния $D_V$.
4. При replay дождаться stream watermark $V$ и применить все переданные релевантные изменения до $V$, даже если в интервале не было событий.
5. После актуализации установить версию фрагмента $V$.

Результат нормализации:

$$
C_Q^V=Normalize(C_Q,V)=\{(I_i,Rows_i^V,V)\}_{i=1}^{s}.
$$

Все фрагменты $C_Q^V$ имеют общую версию $V$. Их корректность проверяется отдельно через сравнение с эталоном.

## Глобальный инвариант после нормализации

### 7. Глобальная уникальность `rowId`

После приведения всех проверяемых фрагментов к версии $V$ количество различных `rowId` во всём состоянии клиента должно совпадать с общим количеством хранимых строк:

```math
\left| \{ rowId(r) \mid \exists i:\ r \in Rows_i^V \} \right|
=
\sum_i |Rows_i^V|
```

## Процедура эталонной проверки

Проверка выполняется через barrier для выбранной версии $V$.

1. Остановить генератор изменений.
2. Дождаться завершения всех начатых атомарных групп изменений и зафиксировать текущую серверную версию $V$.
3. Выполнить $Normalize(C_Q,V)$: для каждого проверяемого фрагмента применить доступный replay либо повторно получить диапазон из $D_V$.
4. При replay дождаться stream watermark $V$, подтверждающего передачу всех релевантных изменений до $V$, и применить их. Подтверждение требуется и при отсутствии релевантных событий.
5. Для каждого материализованного диапазона $I_i$ вычислить эталонный фрагмент из состояния $D_V$: $F_i=F(Q,I_i,V)$.
6. Для каждого фрагмента проверить:
   - уникальность `rowId` внутри фрагмента;
   - принадлежность ключей $K_Q(r)$ диапазону $I_i$;
   - совпадение набора `rowId` с $F_i$;
   - совпадение ключей $K_Q$ и значений $Value_Q$ с $F_i$;
   - корректный порядок строк.
7. Для всего нормализованного состояния $C_Q^V$ проверить глобальную уникальность `rowId` и непересечение материализованных диапазонов.

Клиентское состояние на версии $V$ считается корректным, если все проверки выполнены успешно.
