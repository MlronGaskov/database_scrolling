# Инварианты и процедура эталонной проверки

Пусть состояние клиента $C_Q={f_1,f_2,\ldots,f_s},$ где $f_i=(I_i,Rows_i,v_i)$ - материализованный фрагмент, а $F_i=F(Q,I_i,v_i)$ - эталонный серверный фрагмент для того же запроса, диапазона и watermark.

Клиентское представление считается корректным, если выполняются следующие инварианты.

## Инварианты

### 1. Уникальность `rowId`

Каждый `rowId` встречается в материализованном состоянии клиента не более одного раза:

$$  
\forall id:\ count_{\bigcup_i Rows_i}(id)\le 1.  
$$

### 2. Принадлежность диапазону

Пусть $I_i=[K_{lo}^{(i)},K_{hi}^{(i)})_Q.$

Каждая строка фрагмента принадлежит его диапазону:

$$  
\forall r\in Rows_i:  
K_{lo}^{(i)}\preceq_Q K_Q(r)\prec_Q K_{hi}^{(i)}.  
$$

Строки вне $I_i$ во фрагменте отсутствуют.

### 3. Корректный порядок

Строки каждого фрагмента расположены согласно порядку $\prec_Q$:

$$  
r_1\prec_Q r_2\prec_Q\ldots\prec_Q r_n.  
$$

### 4. Полнота диапазона

Фрагмент содержит все строки результата $R(Q,v_i)$, принадлежащие диапазону $I_i$:

$$  
Ids(Rows_i)=Ids(F(Q,I_i,v_i)).  
$$

### 5. Корректность значений

Для каждого `rowId` значения строки на клиенте совпадают со значениями эталонного серверного фрагмента:

$$  
\forall r\in Rows_i:  
Values(r)=Values(F_i[rowId(r)]).  
$$

### 6. Отсутствие пропущенных релевантных изменений

Для фрагмента с watermark $v_i$ должны быть отражены эффекты всех атомарных групп изменений с watermark не больше $v_i$, влияющих на результат запроса $Q$ в диапазоне $I_i$.

Фрагмент не может иметь watermark $v_i$, если хотя бы одна такая группа изменений была пропущена или применена частично.

### 7. Непересечение материализованных диапазонов

Диапазоны различных фрагментов не пересекаются:

$$  
\forall i\ne j:  
I_i\cap I_j=\varnothing.  
$$

## Процедура эталонной проверки

Проверка выполняется через barrier для выбранного watermark $V$.

1. Остановить генератор изменений.
2. Дождаться завершения всех начатых атомарных групп изменений и зафиксировать текущий серверный watermark $V$.
3. Довести клиентский event stream до $V$: клиент должен применить все релевантные ему атомарные группы изменений с watermark не больше $V$.
4. После достижения barrier $V$ каждый проверяемый фрагмент должен иметь watermark $V$: $f_i=(I_i,Rows_i,V).$
5. Для каждого материализованного диапазона $I_i$ выполнить прямой серверный SQL/OData-запрос к состоянию $D_V$ с теми же условиями фильтрации, сортировки и границами диапазона и получить $F_i=F(Q,I_i,V).$
6. Для каждого фрагмента автоматически проверить:
    - уникальность `rowId`;
    - отсутствие строк вне $I_i$;
    - совпадение набора `rowId` с $F_i$;
    - совпадение значений строк;
    - совпадение порядка строк.
7. Проверить непересечение всех материализованных диапазонов: $\forall i\ne j: I_i\cap I_j=\varnothing.$

Клиентское состояние на watermark $V$ считается корректным, если все проверки выполнены успешно.
