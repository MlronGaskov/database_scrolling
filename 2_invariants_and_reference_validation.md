# Инварианты и процедура эталонной проверки

Пусть состояние клиента $C_Q=(M_Q,G_Q)$, а $f_i=(I_i,Rows_i,v_i)\in M_Q$ - материализованный фрагмент.

Эталонное состояние этого диапазона определяется как $F_i=F(Q,I_i,v_i)$.

Клиентское представление считается корректным, если для каждого материализованного фрагмента выполняются следующие инварианты.

## Инварианты

### 1. Уникальность `rowId`

Внутри одного фрагмента каждый `rowId` встречается не более одного раза: $\forall id:\ count_{Rows_i}(id)\le 1.$

### 2. Принадлежность диапазону

Каждая строка фрагмента принадлежит его диапазону: $\forall r\in Rows_i:\ B_{lo}\preceq_Q r\prec_Q B_{hi}$.

### 3. Корректный порядок

Строки фрагмента расположены согласно порядку $\prec_Q$: $r_1\prec_Q r_2\prec_Q\ldots\prec_Q r_n$.

### 4. Полнота диапазона

Фрагмент содержит все строки результата $R(Q,v_i)$, принадлежащие диапазону $I_i$: $Ids(Rows_i)=Ids(F(Q,I_i,v_i))$.

### 5. Корректность значений

Для каждого `rowId` значения строки на клиенте совпадают со значениями эталонного серверного результата: $\forall r\in Rows_i:\ Values(r)=Values(F_i[rowId(r)])$.

### 6. Отсутствие пропущенных релевантных изменений

Для фрагмента с watermark $v_i$ должны быть отражены эффекты всех изменений журнала с watermark не больше $v_i$, влияющих на результат запроса $Q$ в диапазоне $I_i$.

Фрагмент не может считаться актуализированным до $v_i$, если такое изменение было пропущено.

### 7. Согласованность пересечений

Для двух фрагментов $f_i=(I_i,Rows_i,v), f_j=(I_j,Rows_j,v)$ с одинаковым watermark и $I_i\cap I_j\ne\varnothing$ их состояния на пересечении должны совпадать по `rowId`, значениям и порядку строк.

Фрагменты с различными watermark сравниваются только после доведения до общего watermark.

## Процедура эталонной проверки

Проверка выполняется через barrier для выбранного watermark $V$.

1. Остановить генератор изменений.
2. Дождаться завершения уже начатых изменений и зафиксировать текущий серверный watermark $V$.
3. Довести клиентский event stream до $V$. Клиент должен получить подтверждение, что все события журнала до $V$ обработаны, включая отсутствие дополнительных релевантных событий для конкретного диапазона.
4. После достижения $V$ считать каждый материализованный фрагмент имеющим состояние $f_i=(I_i,Rows_i,V)$.
5. Для каждого материализованного диапазона $I_i$ выполнить прямой серверный SQL/OData-запрос с теми же условиями фильтрации, сортировки и границами диапазона и получить $F_i=F(Q,I_i,V)$.
6. Для каждого клиентского фрагмента автоматически проверить:
    - уникальность `rowId`;
    - отсутствие строк вне $I_i$;
    - совпадение набора `rowId` с $F_i$;
    - совпадение значений строк;
    - совпадение порядка строк.
7. Для всех пересекающихся материализованных диапазонов проверить совпадение состояния на пересечении.

Клиентское состояние на watermark $V$ считается корректным, если все проверки завершились успешно.
