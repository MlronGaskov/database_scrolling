# Сравнение протоколов и сервисов для live-данных

## Решения:

1. **Base OData query** - стандартный способ доступа к структурированным данным через OData.

2. **OData track-changes / delta** - дополнительная возможность OData для получения изменений в структурированных данных.

3. **Microsoft Graph Delta Query** - способ доступа к изменениям в отдельных коллекциях Microsoft Graph.

4. **Base GraphQL query** - способ запрашивать нужные данные через GraphQL API с указанием нужных полей и связей.

5. **GraphQL subscription** - стандартный тип операции GraphQL для получения данных в виде потока событий.

6. **GraphQL Live Query** - нестандартный механизм поверх GraphQL, при котором сервер поддерживает результат запроса актуальным и отправляет его обновления.

7. **Google Cloud Firestore** - API доступа к документам и коллекциям базы данных Firestore.

8. **RethinkDB changefeeds** - встроенный механизм RethinkDB для получения изменений данных из этой БД.

9. **HTTP Conditional GET** - стандартный механизм HTTP для проверки, изменился ли HTTP-ресурс, доступный по URI.

10. **Meteor Livequery with MongoDB** - механизм Meteor для реактивной работы с результатами запросов к MongoDB.

## Таблица 2. Работа с изменениями

1. **Решение** - способ доступа к данным или ресурсам.

3. **Что нужно получить сначала** - какие данные или маркер нужно получить перед дальнейшим отслеживанием изменений.
4. **Что сообщает сервер** - какую информацию получает клиент при изменении данных.
5. **Как приходят изменения** - каким способом клиент получает изменения.
6. **Переход от чтения к слежению** - связь первоначального получения данных с началом отслеживания. Есть ли промежуток, в котором изменение может быть потеряно.

8. **Если история/маркер устарел** - что происходит, если сохранённый маркер состояния больше нельзя использовать.

## Таблица 3. Обнаружение возможностей

1. **Решение** - способ доступа к данным или ресурсам.
2. **Можно ли узнать о поддержке возможности** - может ли клиент сам определить, поддерживает ли сервер нужную функцию.
3. **Как это определяется** - откуда клиент получает эту информацию.
4. **Если возможности нет** - каким базовым способом можно продолжить работу без этой функции.

| Решение                           | Можно ли узнать о поддержке возможности | Как это определяется                                                                                | Если возможности нет                                                  |
| --------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| **Base OData query**              | Да                                      | Через `$metadata` OData-сервиса                                                                     | N/A                                                                   |
| **OData track-changes / delta**   | Да                                      | В `$metadata` поддержка может быть указана через `Capabilities.ChangeTracking`                      | Использовать обычный OData query без отслеживания изменений           |
| **Microsoft Graph Delta Query**   | Частично                                | Поддержка `delta` зависит от конкретного ресурса и указывается в документации Microsoft Graph       | Использовать обычные запросы Microsoft Graph без delta                |
