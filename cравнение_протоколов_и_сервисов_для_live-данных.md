# Сравнение протоколов и сервисов для live-данных

### Решения:

1. **Base OData query** - стандартный способ запрашивать структурированные данные через OData API.

2. **OData track-changes / delta** - возможность OData для получения изменений в выбранном наборе структурированных данных.

3. **Microsoft Graph Delta Query** - механизм Microsoft Graph для получения изменений в данных Microsoft 365.

4. **Base GraphQL query** - способ запрашивать данные через GraphQL API с выбором нужных полей и связанных объектов.

5. **GraphQL subscription** - стандартный механизм GraphQL, при котором сервер отправляет клиенту данные при возникновении событий, определённых API.

6. **GraphQL Live Query** - расширение GraphQL для поддержания сервером актуального результата запроса и отправки его обновлений клиенту.

7. **Google Cloud Firestore** - API документной базы данных Firestore для запросов к документам и коллекциям.

8. **RethinkDB changefeeds** - встроенный механизм RethinkDB для получения изменений JSON-документов и результатов ReQL-запросов.

9. **HTTP Conditional GET** - стандартный механизм HTTP для проверки, изменилось ли представление ресурса, доступного по URI.

10. **Meteor Livequery with MongoDB** - механизм Meteor для синхронизации с клиентом набора документов MongoDB, опубликованного сервером.

11. **ISTREAM** - расширение OData для работы с отдельными упорядоченными фрагментами результата запроса и их изменениями.

3. **Начальная синхронизация** - какие данные нужно получить до работы с изменениями.

4. **Семантика изменений** - что означает полученное изменение.

5. **Способ доставки изменений** - как клиент получает изменения.

6. **Переход от чтения к слежению** - как первоначальное состояние связывается с последующими изменениями и есть ли риск потерять изменение между чтением и началом слежения.

8. **Устаревание истории / повторная синхронизация** - что происходит, если сохранённую позицию или историю изменений больше нельзя использовать.
